1. 미리보기와 발행은 다릅니다

‘미리보기’는 공개하기 전 결과를 확인하는 기능이고, ‘발행’은 편집 내용을 공개 페이지에 반영하는 동작입니다. 편집 중 바뀐 값이 방문자에게 즉시 보인다고 가정하지 마세요.

  1. 편집 중 미리보기 버튼을 눌러 콘텐츠와 링크를 검사합니다.
  2. 오류가 없으면 상단의 ‘발행’을 실행합니다.
  3. ‘발행 중’ 상태가 끝났는지 확인합니다.
  4. 공개 주소를 별도 브라우저나 시크릿 창에서 열어 결과를 확인합니다.
실무 참고발행 결과가 다르게 보인다면 먼저 올바른 페이지와 주소를 보고 있는지 확인하고, 필요하면 새로고침 후 재검증합니다.

2. 편집 기록과 파일 백업

상단에는 실행 취소·다시 실행 기능이 있습니다. 지원되는 편집 상황에서는 Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z로 되돌릴 수 있습니다. 편집 메뉴에는 파일 저장과 파일 복원 기능이 있습니다.

  1. 수정 전 현재 편집본을 파일로 저장해 안전하게 보관합니다.
  2. 파일 복원을 수행할 경우 기존 편집 내용이 바뀔 수 있다는 점을 확인합니다.
  3. 복원 후 미리보기를 반드시 확인합니다.
  4. 복원한 내용 역시 공개하려면 별도로 발행합니다.
실무 참고백업 파일에는 고객이 작성한 개인정보와 다른 데이터를 임의로 포함시키지 말고, 저장 위치와 접근 권한을 관리합니다.

3. 배포 후 꼭 해야 할 QA

기능이 작동하는지 확인하는 마지막 단계입니다.

  1. 신청 버튼과 외부 링크를 모두 클릭합니다.
  2. 휴대폰에서 폼 필수값과 접수 완료 화면을 시험합니다.
  3. 접수함에서 실제 레코드가 생성되었는지 확인합니다.
  4. 모바일 최하단 푸터·고정 버튼 영역을 점검합니다.
실무 참고애드센스나 검색엔진의 색인 결과는 발행 즉시 갱신된다고 보장할 수 없습니다. 공개 페이지가 정상 동작하는지와 검색 색인을 분리해 관리하세요.

실제 화면 따라하기 · 설정 예제

페이지로는 브라우저에 보이는 편집본과 실제 방문자가 보는 발행본을 구분합니다. 배포 여부는 단순히 버튼을 누른 횟수가 아니라 공개 URL에서 검증한 결과로 판단합니다.

1. 편집본, 미리보기, 발행본 비교

항목역할방문자에게 공개 여부
편집 화면블록과 페이지 설정 수정수정 중인 상태만으로는 공개 보장 안 됨
미리보기수정 결과 시각적 점검미리보기 자체는 공개 절차가 아님
발행편집 내용을 공개 페이지에 반영발행 완료 후 공개 URL로 확인
파일 저장편집본을 JSON 백업 파일로 보관공개 내용 변경 없음
파일 복원백업 편집본으로 교체복원 후 별도 발행 필요

2. 광고 집행 전 공개 페이지 점검

  1. 편집 상단에서 미리보기를 열어 모바일 배치를 확인합니다.
  2. 스크롤 최하단까지 내려가 하단 고정 버튼이 신청 버튼과 겹치는지 확인합니다.
  3. 상단의 ‘발행’을 실행하고 발행 중 상태가 끝난 뒤 공개 URL을 확인합니다.
  4. 별도 기기 또는 시크릿 창에서 공개 URL을 열어 최신 제목·이미지·버튼과 푸터가 보이는지 확인합니다.
  5. 방문 화면에서 신청 한 건을 시험하고 접수함 기록을 대조합니다.
  6. 광고 소재에 사용할 최종 URL이 방금 검증한 주소와 같은지 확인합니다.

3. 변경사항이 반영되지 않는 상황

증상우선 확인하지 말아야 할 조치
상단에 ‘미적용’ 상태페이지 설정 값이 편집본에 반영됐는지확인 없이 페이지 초기화
공개 페이지가 구버전발행 완료 여부·접속한 URL·캐시기존 공유 URL을 즉시 삭제
파일 복원 후 예전 화면복원 시점·미리보기·재발행검증 없이 기존 콘텐츠 덮어쓰기
접수 폼만 동작하지 않음필수값·중복 정책·접수함 저장사용자에게 동일 신청 반복 요구

‘발행됨’ 표시보다 먼저 확인해야 할 여섯 가지

페이지로의 편집 변경은 브라우저에 임시보관되는 상태와 공개 URL에 반영되는 상태가 다릅니다. 편집기에는 브랜드·핵심 문구·문의 행동·문의 항목·연락처/사업자·공개 URL 여섯 가지 항목을 확인하는 발행 점검 목록이 구현되어 있습니다. 이 점검은 실무 준비도를 살피는 기준이며, 표시된 개수만으로 모든 고객 접수 동작을 보증하지 않습니다.

현재 발행 점검 목록 6개와 부족한 경우

점검 항목실제 검사 기준의 취지미흡할 때 수정할 곳
브랜드페이지 제목 또는 상단 로고 텍스트페이지 기본·상단 메뉴
핵심 문구히어로 제목·설명 존재히어로 블록
문의 행동유효한 버튼 연결이나 폼·예약 블록버튼·하단 고정 버튼·폼
문의 항목연락처와 문의 맥락을 파악할 수 있는 입력상담 폼·예약 추가 입력
연락처/사업자푸터 회사명과 연락 수단·주소 등푸터
공개 URL임시 예시가 아닌 페이지 주소페이지 설정·주소

예를 들어 발행 목록에서 문의 항목이 미흡하게 표시된다면 이름과 연락처만 있는 폼인지, 목적을 파악할 추가 질문이 있는지 확인합니다. 다만 항목을 기계적으로 늘리기보다 고객이 신청하는 데 필요한 최소한의 정보만 수집하세요. 모든 점검 항목이 채워졌더라도 법적 고지의 적정성이나 외부 서비스의 정상 작동이 자동으로 검증되지는 않습니다.

상태 메시지를 실제 동작과 연결하기

표시·상황의미검증 방법
브라우저에 임시저장됨작성한 값이 임시보관된 상태공개 주소 변경을 가정하지 않음
발행 중 또는 공개 반영 확인 중발행·공개 확인 절차 진행처리 완료 뒤 공개 URL 새 창 확인
발행됨발행이 성공으로 기록된 상태방문자 주소에서 제목·문의 버튼 확인
공개 반영 확인 필요저장과 공개 확인을 다시 대조할 상황주소·기기·캐시 확인 후 재검증

현재 코드에는 화면 이동 시 발행하지 않은 변경사항이 있다는 안내도 있습니다. 작성 중이라면 실수로 이동해 변경을 잃지 않도록 확인하고, 발행 전에 현재 편집본을 백업해 두면 복구 판단이 쉬워집니다.

가상 패치 1건의 배포 판정표

  1. 변경 전: 수정할 페이지의 공개 URL과 원래 문구를 기록합니다.
  2. 변경: 히어로 제목만 예시 문구로 바꾸고, 미리보기에서 확인합니다.
  3. 발행: 발행을 실행하고 처리 상태를 확인합니다. 편집 자동 임시보관은 발행을 대신하지 않습니다.
  4. 공개 검증: 시크릿 창 또는 다른 기기에서 정확한 공개 주소를 열어 변경된 제목이 보이는지 확인합니다.
  5. 문의 검증: 가능하면 동의한 테스트 담당자의 가상 신청으로 완료 화면과 접수함 기록을 각각 확인합니다.
  6. 이상 발생: 현재 페이지를 삭제하거나 주소를 바꾸기 전, 발행 상태·기존 URL·테스트 결과를 남겨 원인을 좁힙니다.

자주 묻는 질문

미리보기만 최신으로 보이는 이유는?

공개 페이지로 발행되지 않았거나 다른 URL을 보고 있을 수 있습니다. 발행 상태와 시크릿 창 결과를 확인하세요.

백업 복원만 하면 공개 페이지가 바뀌나요?

파일 복원은 편집본을 변경합니다. 확인 후 다시 발행해야 공개 내용에 반영됩니다.
