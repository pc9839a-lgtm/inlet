문제 해결: 발행이 안 보일 때·폼 접수 누락·통계 차이

페이지로 공개 페이지와 편집기에서 자주 발생하는 현상을 증상별로 진단하고 실제 확인해야 할 화면과 기록을 안내합니다.

  5. 완료 점검

1. 수정했는데 공개 페이지에 안 보입니다

편집 중 변경이 공개 주소에 즉시 적용되는 것은 아닙니다. 미리보기에서만 변경사항이 보이는 경우 먼저 발행 상태를 확인합니다.

  1. 상단 버튼이 ‘발행됨’ 상태인지 확인합니다.
  2. 다른 페이지를 편집한 것은 아닌지 제목·주소를 확인합니다.
  3. 공개 주소를 시크릿 창에서 다시 엽니다.
  4. 캐시나 이전 탭의 영향을 배제한 뒤 계속되면 백업·복원 기록을 검토합니다.
실무 참고보이지 않는다고 무조건 다시 생성하거나 기존 페이지를 삭제하지 마세요. 기존 URL을 유지한 채 원인을 확인하는 편이 안전합니다.

2. 완료 메시지가 떴는데 접수함에 없습니다

사용자 화면, 서버 저장, 외부 알림은 서로 다른 단계입니다.

  1. 테스트 접수 시각과 이용한 공개 URL을 기록합니다.
  2. 접수함의 전체 문의에서 조회 월과 필터를 초기화해 다시 검색합니다.
  3. 스팸·중복 분류 및 필수 입력 차단 여부를 확인합니다.
  4. 실제 접수 데이터가 없다면 제출 동작을 새로 재현하고 네트워크 오류를 조사합니다.
실무 참고접수함에 저장되어 있는데 외부 알림만 실패했다면 ‘전송 내역’ 문제로 분류해 해결합니다.

3. 광고 전환 숫자와 실제 문의 숫자가 다릅니다

광고 픽셀·버튼 클릭·폼 시작·제출 성공은 모두 다른 이벤트입니다.

  1. 동일 기간과 시간대로 비교합니다.
  2. 테스트 트래픽이나 중복 이벤트를 제외합니다.
  3. 페이지로 통계의 제출 성공과 접수함 내역을 먼저 비교합니다.
  4. 광고 플랫폼의 이벤트 설정과 실제 전송 시점을 확인합니다.
실무 참고이 차이는 반드시 오류를 의미하지 않습니다. 무엇을 ‘전환’으로 정의했는지에 따라 차이가 발생할 수 있습니다.

4. 화면이 잘리거나 버튼이 눌리지 않습니다

모바일 화면·이미지 크기·고정 버튼·외부 삽입 환경의 영향을 분리해 봅니다.

  1. 모바일 360·390·430px 폭으로 각각 확인합니다.
  2. 하단 고정 영역이 폼 입력과 겹치는지 확인합니다.
  3. 특정 블록에서만 발생하는지 새로 만든 테스트 페이지와 비교합니다.
  4. 문제가 있는 브라우저·기기·주소·재현 단계를 기록합니다.
실무 참고재현 기록이 자세할수록 기능 문제와 콘텐츠 설정 문제를 빠르게 구별할 수 있습니다.

완료 점검

이 문서를 마치기 전에 확인하세요.
  • 증상과 URL·발생 시각을 기록했는가
  • 발행·접수 저장·외부 전송을 구별했는가
  • 필터와 테스트 데이터 영향을 제거했는가
  • 모바일 기기에서도 동일한 문제를 재현했는가
