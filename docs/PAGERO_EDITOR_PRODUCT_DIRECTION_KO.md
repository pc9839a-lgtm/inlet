- 갱신일: 2026-10-23 KST
- 범위: PageRo 페이지 제작·편집·미리보기·발행 경험
- 선행조건: 저장소/문서 정리와 release blocker 안정화가 우선

- 구현 상태: E0~E4 main 반영 완료 / E5는 실사용 데이터 이후
- 현재 우선순위는 이 문서가 아니라 `PAGERO_INTERNAL_OPTIMIZATION_MASTER_KO.md` 단일 미해결 등록표를 따른다. E0~E4, P6, P9 코드/QA는 완료; P5 운영 기반 완료·별도 외부 도메인 smoke만 후순위; P7 실제 PG는 홀드. 배포 승인 우회(DEP-00) 대응 전 편집기 재개편을 신규 과제로 반복하지 않는다.
- 현재 사용자 제약: 편집기 개편에 AI 생성·채팅·추천·자동 코드 해석을 추가하거나 연결하지 않는다. 아래 E4 설명은 과거 구현 방향이며 현재 작업 지시가 아니다.
- 현재 편집기 개편은 아래 11절의 사용자 제약과 판정 기준을 우선 적용한다. E0~E4의 과거 구현 완료는 현재 화면의 디자인 수용을 뜻하지 않는다.

## 1. 초기 문제 정의 (E0~E4 계획 수립 당시)

아래는 E0~E4 개발의 원래 문제 정의와 제품 방향을 보존한 내용이다. **현재 main에서 새로 확인된 미해결 버그라는 의미가 아니다.** 실제 남은 위험/검증 공백은 마스터 문서의 현재 미해결 등록표에서만 판정한다.

당시 주요 개선 대상:

- 편집 경험이 관리자 설정 화면처럼 느껴짐
- 블록 목록, 상세 설정, 스타일, 설정 탭 간 이동 비용이 큼
- 화면을 보면서 직접 고친다는 느낌보다 폼을 수정한다는 느낌이 강함
- 기능 수에 비해 템플릿/패턴의 완성도가 제품 가치를 충분히 전달하지 못함
- 문의 수집 이후의 PageRo/CallTag 강점이 편집 과정에서 연결되지 않음
- 사용자가 첫 공개 페이지를 빠르게 완성하게 만드는 제품 흐름이 약함

## 2. 경쟁 기준

PageRo는 범용 웹사이트 빌더의 모든 기능을 따라가지 않는다.

### Carrd

Carrd는 단순한 반응형 one-page 제작, 템플릿, 폼, 커스텀 도메인과 낮은 진입비용이 강점이다.

PageRo가 Carrd보다 더 복잡하면서 리드 운영 이점이 보이지 않으면 선택 이유가 없다.

### Framer / Wix Studio

Framer와 Wix Studio는 시각적 캔버스, 높은 디자인 자유도, 반응형 제작, 폼/통합 기능이 강하다.

PageRo는 이들과 픽셀 단위 디자인 자유도로 경쟁하지 않는다.

### Typedream

Typedream은 빠른 콘텐츠 편집, 템플릿, 폼, CMS, analytics, custom domain을 한 제품에 묶는다.

PageRo는 단순한 빠른 사이트 제작만으로는 차별화가 부족하다.

### Unbounce

Unbounce는 랜딩페이지 제작뿐 아니라 lead, integrations, A/B test, conversion optimization을 제품 핵심으로 둔다.

PageRo가 장기적으로 참고해야 할 방향은 범용 디자인 툴보다 이쪽에 가깝다.

참고:
- https://carrd.com/
- https://www.framer.com/help/articles/how-can-i-add-a-contact-form-to-my-framer-website/
- https://typedream.com/docs
- https://unbounce.com/product/features/
- https://www.wix.com/studio

## 3. PageRo가 가져야 할 한 문장 가치

**광고용 문의 페이지를 빠르게 만들고, 들어온 문의를 바로 관리하고, 어떤 광고에서 전환됐는지까지 한곳에서 보는 도구.**

PageRo의 차별화는 예쁜 페이지 자체가 아니라 아래 end-to-end 흐름이어야 한다.

`페이지 제작 → 광고 유입 → 문의 제출 → 접수함/CallTag → 전화·문자·일정 → 전환 확인`

## 4. 편집기 목표

### 목표 1 — 10분 안에 첫 공개

신규 사용자가 템플릿 선택 후 다음만 수정해서 바로 공개할 수 있어야 한다.

- 상호/브랜드
- 핵심 문구
- 이미지
- CTA
- 문의 항목
- 연락처/사업자 정보

고급 설정은 첫 제작 흐름에서 뒤로 숨긴다.

### 목표 2 — 화면을 직접 고치는 느낌

E1 수립 당시 데스크톱 구조는 다음과 같았다. 현재 개편에서는 11절의 사용자 지정 배치를 우선하며 아래 배치를 이유로 임의 반전하지 않는다.

- 왼쪽: 구조 / 블록 추가
- 가운데: 실제 페이지 캔버스
- 오른쪽: 현재 선택 요소 설정
- 상단: 뒤로가기 / 페이지명 / Undo / Redo / 미리보기 / 발행

현재도 페이지에서 선택한 블록과 설정 대상은 즉시 일치해야 한다. 설정창의 좌우 위치와 이 동작은 별개로 다룬다.

텍스트, 버튼 문구처럼 안전한 속성은 가능한 범위에서 canvas inline edit을 제공한다.

### 목표 3 — 블록이 아니라 완성된 섹션을 추가

기본 추가 단위를 작은 위젯만으로 두지 않는다.

예:

- 상담형 히어로 + CTA
- 이미지 + 핵심 장점 3개
- 후기/신뢰 섹션
- 가격/혜택 섹션
- 자주 묻는 질문
- 지도/방문 예약
- 문의 폼
- 하단 고정 상담 버튼

사용자는 빈 블록을 조립하기보다 검증된 섹션 패턴을 선택하고 내용을 바꾸는 방식이 기본이어야 한다.

### 목표 4 — 스타일 탭 이동 최소화

선택 블록의 내용/디자인은 같은 inspector 안에서 처리한다.

전역 스타일만 별도 Theme 영역으로 둔다.

- 색상
- 폰트
- 버튼 radius
- 기본 여백
- 배경 톤

현재처럼 편집과 스타일 사이를 자주 왕복하는 흐름은 줄인다.

### 목표 5 — 전환 운영을 편집기에 연결

PageRo만의 이유는 여기서 만든다.

편집기 또는 preview 주변에서 다음을 확인할 수 있어야 한다.

- 폼이 어디로 들어가는지
- 테스트 문의 보내기
- 최근 문의 도착 여부
- UTM/광고 유입 추적 상태
- Meta/Naver/Google tracking 연결 상태
- CTA 클릭/폼 제출 전환 이벤트 상태

일반 웹빌더의 설정 메뉴 깊숙한 곳에 있는 기능이 아니라 **광고 랜딩을 만든 사람이 바로 확인하는 운영 도구**가 되어야 한다.

## 5. 정보 구조 재편

### 상단

남길 것:

- 대시보드
- 페이지명
- Undo / Redo
- 저장 상태
- 미리보기
- 발행

제거/후순위:

- 자주 쓰지 않는 설명
- 상단에서 중복되는 설정 진입점
- 편집과 무관한 운영 메뉴 과노출

### 왼쪽 패널

두 모드만 유지한다.

1. **구조**
   - 섹션 순서
   - 표시/숨김
   - 드래그
   - 복제/삭제
2. **추가**
   - 추천 섹션
   - 업종별 섹션
   - 기본 블록
   - 최근 사용

### 선택 항목 설정 (과거 오른쪽 Inspector)

선택 대상에 따라 내용이 바뀐다.

- 아무것도 선택하지 않음 → 페이지 기본/Theme
- 블록 선택 → 내용 / 디자인 / 동작
- 폼 선택 → 질문 / 제출 후 동작 / 문의 연결
- CTA 선택 → 문구 / 전화·링크 / 추적 이벤트

한 화면에서 같은 설정을 두 군데 노출하지 않는다.

## 6. 템플릿 전략

템플릿 개수를 무작정 늘리지 않는다.

현재 핵심 3종을 먼저 완성도 높게 만든다.

- 개인회생 상담
- 부동산 분양
- 모바일 청첩장

광고/상담형 템플릿은 단순 디자인 템플릿이 아니라 다음을 함께 가져야 한다.

- 추천 폼 필드
- CTA
- 기본 추적 이벤트
- UTM 저장
- 문의 접수 분류
- 업종 맞춤 신뢰 섹션

## 7. 과거 AI 방향 — 현재 편집기 개편에서 제외

이 절은 E4의 과거 제품 방향을 보존한 것이다. 현재 사용자 지시에 따라 AI 기능의 추가·확장·연결은 개편 범위에서 제외한다. 아래 내용을 현재 작업의 기능 제안이나 구현 승인으로 사용하지 않는다.

AI는 별도 장난감 기능이 아니라 첫 페이지 완성 시간을 줄이는 데 사용한다.

사용자 입력:

- 업종
- 서비스명
- 핵심 혜택
- 지역
- 받고 싶은 문의 항목

AI 출력:

- 추천 섹션 구성
- 헤드라인/서브카피
- CTA
- FAQ
- 폼 항목

결과는 반드시 일반 PageRo 블록으로 생성되어 사용자가 직접 수정 가능해야 한다.

## 8. 지금 하지 않을 것

유지보수 안정화 전에는 다음을 우선하지 않는다.

- 자유 좌표 기반 완전한 디자인 캔버스
- Figma 수준의 레이어 시스템
- 다중 breakpoint 수동 디자인
- 복잡한 animation timeline
- 대규모 plugin marketplace
- 범용 CMS 경쟁

이 기능들은 PageRo의 현재 차별화와 출시 속도에 비해 비용이 너무 크다.

## 10. 성공 기준

편집기 리뉴얼은 예뻐졌다는 이유로 완료하지 않는다.

측정 기준:

1. 신규 사용자가 도움말 없이 첫 블록을 수정할 수 있음
2. 템플릿 선택 후 첫 공개까지 불필요한 설정 화면 방문 최소화
3. 페이지 편집 중 현재 선택 대상과 설정 위치를 잃지 않음
4. 발행 전 테스트 문의를 직접 확인 가능
5. 공개 후 문의가 어느 유입에서 왔는지 확인 가능
6. 동일 작업을 기존 편집기보다 적은 클릭으로 완료
7. 사용자에게 PageRo의 차별점이 “페이지 디자인”이 아니라 “문의 전환 운영”으로 인식됨

## 11. 현재 편집기 개편 기준

### 11.1 근거와 잘못 적용한 부분

사용자가 제공한 「국내·해외 노코드 플랫폼 UX/UI 벤치마크 분석 보고서」와 거절한 편집기 캡처를 기준으로 한다. 보고서의 플랫폼 설명은 제공 자료에서 추출한 비교 근거다. 이를 새로 로그인해 확인한 실사용 조사라고 표현하지 않는다. 보고서의 내부 인용 ID는 검증 가능한 출처 링크로 재사용하지 않는다.

| 거절된 화면에서 확인한 문제 | 이전 대응의 오류 | 바꿀 작업 기준 |
| --- | --- | --- |
| 구성 목록과 긴 설정 폼이 화면의 주인공이 됨 | 목록과 폼을 나란히 놓은 것을 직접 편집 UX로 간주 | 페이지에서 선택 → 해당 항목 수정 → 결과 확인 흐름부터 설계 |
| 블록/페이지 설정, 항목 제목, 내용/스타일 탭과 구분선이 반복됨 | 둥근 탭을 밑줄로 바꿔 정보 구조 문제가 해결됐다고 판단 | 동일 문맥의 탐색·제목 중복을 줄이고 기본 편집 작업을 곧바로 노출 |
| 여백 한 값에 슬라이더·숫자·프리셋 네 개를 동시에 노출 | 기능이 많으면 편하다고 판단 | 기본 조작 하나를 정하고 보조 조작은 필요한 경우에만 제공 |
| 일반 블록과 고정 영역의 행·상태 조작이 서로 다름 | 고정 영역을 별도 설정 카드로 계속 취급 | 같은 구성 목록의 항목으로 읽히도록 이름·선택·숨김 상태 규칙 통일 |
| 짧은 항목 이름도 잘리고 설정창에는 불필요한 세로 간격이 남음 | 전체 글자 크기·굵기·간격을 일괄 변경 | 실제 이름과 입력 내용으로 패널 폭·행 구조·그룹 간격을 함께 검토 |
| 기능 검사는 통과했지만 사용자가 화면을 거절함 | CI 성공과 캡처 존재를 디자인 완성의 근거로 보고 | 동작 검증, 시각 비교, 사용자 수용을 분리해 기록 |

### 11.2 보고서 10개 사례를 편집기 판단으로 연결

아래는 제공 보고서의 편집 패턴을 PageRo에 적용할 판단으로 정리한 것이다. AI 관련 기능, 신규 온보딩, 마케팅 홈페이지 개편은 가져오지 않는다. 패널 폭·글자 크기의 시각적 근사치를 경쟁사의 공식 규격처럼 사용하지 않는다.

### 11.3 유지할 사용자 제약

- 왼쪽 편집·오른쪽 실제 페이지, 상시 보이는 구성 목록을 유지한다. 보고서의 일반적인 3영역 예시를 이유로 다시 오른쪽 편집기나 구성 팝업으로 바꾸지 않는다.
- 미리보기는 390px 하나만 노출한다. 여러 폭 버튼과 같은 폭의 중복 측정 문구를 다시 추가하지 않는다.
- 코드 블록은 코드 자체를 직접 편집한다. 코드에서 제목·사진·버튼을 추출하는 자동 입력폼을 만들지 않는다.
- AI 생성·채팅·추천·자동 코드 해석을 이번 개편에 추가·확장·연결하지 않는다.
- 짧은 이름과 직접 조작을 사용한다. 설명 카드·추천 카드·온보딩·기능 소개 문구로 빈 공간을 채우지 않는다.
- 페이지 설정과 항목 설정의 적용 범위를 구분한다. 저장·미리보기·발행 상태를 짧게 표시하고 동작을 유지한다.

### 11.4 대표 설정창 설계 기준

1. **여백:** 기본은 이름 + 숫자/단위 한 칸이다. 블록 사이 간격과 내용 안쪽 간격을 구분하고 페이지의 선택 표시로 위치를 확인할 수 있게 설계한다. 슬라이더와 프리셋을 매 행에 함께 붙이지 않는다. 기존 `paddingY`/`marginY`가 지원하지 않는 네 방향 독립 조절을 제공한다고 표시하지 않는다.
2. **글:** 내용 변경을 곧바로 할 수 있어야 한다. 모양·글자 크기·정렬은 같은 위계로 묶고 작은 옵션마다 카드·중복 제목·탭을 만들지 않는다.
3. **이미지:** 사진 바꾸기를 우선 노출한다. 크기·맞춤을 다음 그룹으로 두고 필터 등은 필요할 때 연다. 썸네일 크기만 줄인 것을 이미지 편집 흐름 개선으로 보고하지 않는다.
4. **코드:** 직접 편집창과 적용 상태를 명확히 한다. 큰 편집창 진입·적용·취소를 검증한다. 코드 내용의 재해석이나 일반 블록용 입력칸을 섞지 않는다.
5. **구성:** 항목 이름이 식별 가능해야 한다. 모든 보조 버튼을 항상 펼치는 대신 메뉴·hover·키보드 focus 상태를 함께 설계한다. 선택·숨김 상태와 필요한 조작 접근성은 보존한다.
6. **공통 스타일:** 위 대표 화면을 실제 콘텐츠로 검토한 다음 공통화한다. 색·테두리·radius·font-weight의 일괄 교체를 개편의 첫 작업으로 삼지 않는다. 숫자 토큰을 경쟁사의 공식값으로 꾸미지 않는다.

### 11.5 작업 순서와 완료 판정

작업 순서는 **편집 흐름과 정보 구조 → 대표 설정창 → 다른 블록에 적용 → 공통 스타일 정리**다. 작은 CSS 변경을 차수로 쌓아 전체 UX 개편이 진전됐다고 보고하지 않는다.

각 변경은 `어느 참고 화면/패턴 → 현재 문제 → 실제 화면에서 바뀔 조작 → 확인 근거`로 설명할 수 있어야 한다. 새 조사를 했다고 주장할 때는 공식 원본 URL과 실제로 본 화면/상태를 기록한다.

검증은 세 가지로 나눈다.

- **동작 검증:** 저장·복구·이미지 조정·코드 적용/취소·키보드·발행 격리. CI 성공은 이 항목의 근거다.
- **시각 비교:** 같은 viewport·선택 상태에서 기준과 결과를 비교한다. 여백, 제목 반복, 이름 잘림, 설정 밀도, 선택 표시를 확인한다. 한글이 깨진 캡처는 통과 자료로 쓰지 않는다. CI fixture 화면과 사용자의 실제 페이지를 구분한다.
- **사용성/수용:** 사용자의 구체적인 거절은 미해결로 남긴다. 사용자 시험이 없으면 쉽다고 검증했다고 쓰지 않으며, 테스트 통과를 사용자 수용으로 바꾸어 말하지 않는다.

사용자가 현재 화면을 거절한 상태에서 색과 테두리만 바꾼 결과를 디자인 완료로 선언하지 않는다. 실제 작업 상태와 다음 할 일은 마스터 문서에서 관리한다.
