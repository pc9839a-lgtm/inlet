# 회원가입 인증번호 저장 호환 긴급 패치

## 장애

운영 API가 `EMAIL_VERIFICATION_STORAGE_FAILED`를 반환해 회원가입 인증메일이 발송 단계까지 도달하지 못했다. 페이지로 접수메일은 별도 경로라 정상 수신됐다.

## 원인

인증번호 목적 분리와 일회성 소비 패치가 D1 기존 상태값에 없는 `superseded`, `consumed`를 쓰도록 변경됐다. 운영 D1 스키마를 별도 마이그레이션하지 않은 상태에서 해당 상태 저장이 실패할 수 있었다.

## 수정

- 같은 이메일·목적의 이전 인증번호: `expired` 처리
- 최종 사용된 인증번호: 기존 허용 상태 `blocked`와 `confirmed_at` 조합으로 소비 표시
- `blocked + confirmed_at`: 이미 사용된 코드로 판정
- `blocked + confirmed_at 없음`: 오입력 횟수 초과 차단으로 판정
- 외부 응답은 기존처럼 `consumed`를 유지
- 운영 D1 마이그레이션 없음
- SES·접수메일 설정 변경 없음

## 검증

- 새 코드 발급 시 이전 코드 무효화
- 확인 후 최종 작업 1회만 허용
- 사용된 코드 재사용 409 차단
- 잘못된 목적 격리
- 인증 이메일·Pages Functions·API 보안·프로덕션 빌드
