# Pagero 데스크톱 블록 편집기 현대화 명세 v2

- 문서 상태: 구현 최우선 기준
- 작성일: 2026-07-13
- 기준 브랜치: `integrate/pagero-internal-page-split-safe`
- 기준 커밋: `cda222f`
- 적용 범위: 데스크톱 워크스페이스의 화면 순서 목록과 인라인 블록 편집기
- 이전 문서: `docs/editor-block-editor-ux-ui-spec.md`
- 우선순위: 이 문서가 이전 편집기 UI 문서와 충돌할 경우 이 문서를 따른다.

## 1. 목표

Pagero 블록 편집기를 오래된 관리자 페이지 형태에서 현대적인 속성 패널 형태로 전환한다.

목표 화면은 다음 특성을 갖는다.

- 흰색 중심의 평평한 패널
- 얇은 구분선
- 상단 탭
- 접을 수 있는 설정 섹션
- 명확한 라벨과 입력 컨트롤
- 최소한의 설명문
- 화면 순서 행에서 즉시 사용할 수 있는 조작 버튼
- 카드 안에 카드를 반복하지 않는 정보 구조

이번 작업은 단순 CSS 보정이 아니다. 화면 순서 행의 동작, 조작 버튼 노출, 편집기 정보 구조와 시각 체계를 함께 정리한다.

## 2. 절대 보존할 기능

아래 기능은 삭제하거나 `더보기` 메뉴 안에 숨기지 않는다.

- 블록 표시 여부 전환
- 위로 이동
- 아래로 이동
- 블록 복제
- 블록 삭제
- 드래그 순서 변경
- 블록 열기
- 열린 블록 다시 클릭하여 닫기
- 변경 즉시 미리보기 반영
- 기존 페이지 저장 흐름
- 블록별 lazy import
- 기존 블록 데이터 스키마

기능이 화면에서 보이지 않으면 코드에 남아 있더라도 UX상 삭제된 것으로 판단한다.

## 3. 수정 금지 영역

이번 작업은 내부 데스크톱 편집기만 수정한다. 아래 영역은 자동 수정하지 않는다.

- 운영 루트 `/`
- frozen C63 메인
- `index.html`
- `src/main.jsx`
- `src/App.jsx`의 홈 및 루트 라우팅
- `src/routes/*`
- `src/runtime/AppRuntimeRouter.jsx`
- `src/runtime/AppRouteScreens.jsx`
- `functions/*`
- `server/index.mjs`
- `src/styles/base-public*.css`
- 공개 홈 및 공개 랜딩 렌더러
- 모바일 편집 기능

모바일에서는 기존 결정대로 접수함과 통계만 제공한다. 모바일 편집 UI는 이번 명세의 대상이 아니다.

## 4. 디자인 기준

### 4.1 전체 인상

참고 화면과 같은 속성 패널 문법을 사용한다.

- 패널 배경: 흰색
- 페이지 배경: 매우 연한 회색
- 섹션 구분: `1px` 가로선
- 기본 모서리: `8px`
- 큰 컨테이너 모서리: 최대 `10px`
- 그림자: 기본적으로 사용하지 않음
- 활성 상태: 진한 글자, 하단선 또는 약한 배경
- 위험 동작: 빨간색은 삭제 동작에만 사용

금지:

- 굵은 파란색 또는 청록색 외곽선 반복
- 카드 안에 카드 중첩
- 큰 그림자
- 모든 영역을 둥근 박스로 감싸기
- 설명문을 입력 항목마다 반복
- 블록 이름과 `OO 편집` 제목을 연속 표시
- 주요 기능을 `...` 메뉴에 숨기기

## 5. 화면 순서 행

### 5.1 데스크톱 기본 구성

```text
[드래그] [번호] [아이콘] 블록명    [표시] [위] [아래] [복제] [삭제] [접기]
```

각 기능은 한 줄에서 직접 접근할 수 있어야 한다.

- 드래그 핸들: 기존 동작 유지
- 번호: 현재 순서 표시
- 아이콘과 블록명: 클릭 가능한 주 선택 영역
- 표시 토글: 기존 `toggleVisible` 사용
- 위/아래: 기존 `reorderToIndex` 사용
- 복제: 기존 `duplicateBlock` 사용
- 삭제: 기존 `removeBlock` 사용
- 접기: 현재 열림 상태 표시

### 5.2 버튼 규칙

- 아이콘은 `lucide-react`를 사용한다.
- 위: `ArrowUp`
- 아래: `ArrowDown`
- 복제: `Copy`
- 삭제: `Trash2`
- 접기: `ChevronDown` 또는 `ChevronUp`
- 모든 아이콘 버튼에 `title`과 `aria-label`을 제공한다.
- 첫 블록의 위 이동과 마지막 블록의 아래 이동만 비활성화한다.
- 싱글톤 블록은 복제 버튼을 비활성화하거나 숨길 수 있다.
- 삭제 버튼은 기본 회색이고 hover/focus에서만 빨간색을 강조한다.
- 버튼 클릭은 반드시 행 클릭 이벤트 전파를 차단한다.

### 5.3 열기와 닫기

현재 `useNormalBlockSelection.selectBlock`은 같은 블록을 다시 눌러도 열기만 한다. 아래 계약으로 변경한다.

```text
닫힌 행 클릭 -> 해당 편집기 열기
열린 행 클릭 -> 해당 편집기 닫기
다른 행 클릭 -> 기존 편집기 닫기 + 새 편집기 열기
조작 버튼 클릭 -> 열림 상태 변경 없음
```

구현 시 상태 계약:

- 같은 `blockId`가 열려 있으면 `openId`와 `selectedNormalId`를 모두 비운다.
- 다른 `blockId`를 누르면 두 상태를 해당 ID로 설정한다.
- `openBlockSettings`는 메뉴용 토글이 아니라 명시적 열기 함수로 유지할 수 있다.
- 키보드 `Enter`와 `Space`도 동일한 토글 동작을 제공한다.

### 5.4 선택 상태

- 닫힌 행: 흰 배경과 얇은 경계선
- 열린 행: 아주 연한 회색 배경 또는 상단 `2px` 활성선
- 선택 표시는 한 종류만 사용한다.
- 굵은 외곽선, 진한 배경, 큰 그림자를 동시에 사용하지 않는다.
- 열린 편집 영역은 행 바로 아래에 연결되어 하나의 작업 단위로 보여야 한다.

## 6. 인라인 편집기 정보 구조

### 6.1 중복 헤더 금지

화면 순서 행에 이미 `히어로`, `텍스트`, `링크` 등의 이름이 있으므로 내부에 아래 제목을 다시 표시하지 않는다.

- `히어로 편집`
- `텍스트 편집`
- `링크 편집`
- 기타 `블록명 + 편집`

`BlockEditorShell`은 접근성용 `aria-label`과 공통 루트만 제공한다. 시각 헤더를 추가하지 않는다.

### 6.2 상단 탭

선택된 블록의 옵션을 평평한 탭으로 분리한다.

예시:

```text
내용    이미지    효과
────
```

블록별 권장 탭:

| 블록 | 탭 |
|---|---|
| Hero | 내용 / 이미지 / 효과 |
| Text | 내용 / 스타일 / 효과 |
| Image | 이미지 / 레이아웃 / 효과 |
| Links | 내용 / 링크 목록 / 스타일 |
| Cards | 내용 / 카드 목록 / 스타일 |
| Form | 기본 / 입력 항목 / 제출 / 스타일 |
| Reservation | 기본 / 일정 / 입력 항목 / 스타일 |
| TopNav | 로고 / 메뉴 / 스타일 |
| BottomBar | 버튼 / 이동 / 스타일 |
| Footer | 내용 / 링크 / 스타일 |

규칙:

- 옵션이 없는 탭은 표시하지 않는다.
- 탭은 둥근 버튼 카드로 만들지 않는다.
- 활성 탭은 진한 글자와 하단 `2px` 선으로 표시한다.
- 비활성 탭은 회색 글자로 표시한다.
- 탭 전환 시 블록 선택이나 스크롤 위치를 초기화하지 않는다.

### 6.3 탭 내부 섹션

탭 내부는 참고 화면의 `레이아웃`, `효과`처럼 접이식 섹션으로 구성한다.

```text
레이아웃                                      [접기]
--------------------------------------------------
필드
필드

효과                                          [열기]
--------------------------------------------------
```

규칙:

- 섹션을 별도 카드로 만들지 않는다.
- 섹션 사이는 `1px` 가로선으로만 구분한다.
- 섹션 제목과 접기 아이콘을 한 줄에 둔다.
- `내용` 섹션은 처음 열 때 기본으로 펼친다.
- 고급 설정은 기본으로 접는다.
- 열린 섹션은 동시에 여러 개 존재할 수 있다.
- 접기 상태는 같은 블록을 편집하는 동안 유지한다.

## 7. 입력 컨트롤

### 7.1 텍스트 입력

```text
제목
[입력값]

설명
[입력값]
```

- 라벨과 입력을 세로로 배치한다.
- 필드 전체를 카드로 감싸지 않는다.
- 라벨 `13px`, 입력 `14px`를 기본으로 한다.
- input 높이는 `42px`로 통일한다.
- textarea 최소 높이는 `96px`로 한다.
- 입력 사이 간격은 `16px`로 한다.
- 포커스 시 파란 경계선과 약한 focus ring만 표시한다.
- 라벨만으로 의미가 충분하면 설명문을 표시하지 않는다.

### 7.2 세그먼트 컨트롤

참고 화면의 `기본 / 마우스 오버`, `기본 / 직접 지정` 형태를 사용한다.

- 전체 배경은 연한 회색
- 선택 항목은 흰색 또는 진한 배경
- 선택 상태는 색상 하나로 명확히 표현
- 각 버튼 높이는 `36px`
- 옵션이 두세 개일 때만 사용

### 7.3 스위치

- 단일 손잡이만 렌더링한다.
- 꺼짐: 회색 트랙
- 켜짐: 진한 네이비 또는 녹색 트랙
- 손잡이 위치가 상태와 일치해야 한다.
- 라벨은 스위치 왼쪽에 둔다.
- 스위치 행 전체가 클릭 가능해야 한다.

### 7.4 숫자와 단위

- `px`, `%`, `초` 등의 단위는 입력 오른쪽에 고정한다.
- 비활성 입력은 단순히 흐리게만 하지 말고 입력 불가 상태가 명확해야 한다.
- 슬라이더와 숫자 입력을 동시에 제공할 때 값 동기화를 유지한다.

### 7.5 이미지 입력

```text
[기본] [마우스 오버]

+ 이미지를 추가해 주세요

레이아웃
효과
```

- 빈 상태는 얇은 점선 업로드 영역으로 표시한다.
- 중앙에 `Plus` 아이콘과 한 줄 안내만 둔다.
- 이미지가 있으면 미리보기와 교체/삭제 명령을 제공한다.
- 이미지, 레이아웃, 효과를 같은 깊이의 카드로 반복하지 않는다.

## 8. 긴 편집 화면

- 편집기 상단 탭은 해당 인라인 편집 영역 안에서 고정할 수 있다.
- 고정 탭이 화면 전체 워크스페이스 헤더를 덮으면 안 된다.
- 긴 폼에서는 하단에 보조 작업 바를 둘 수 있다.
- 화면 순서 행의 이동/복제/삭제 버튼은 항상 유지한다.
- 하단 작업 바는 행 기능을 대체하지 않는다.

권장 하단 바:

```text
[블록 복제]                                  [블록 삭제]
```

## 10. 단계별 구현 순서

### 1단계: 기능 복원

1. 같은 행 재클릭 시 닫기

## 11. 테스트 시나리오

### 11.1 화면 순서

- 히어로 클릭 시 열린다.
- 열린 히어로를 다시 클릭하면 닫힌다.
- 히어로가 열린 상태에서 텍스트를 누르면 히어로는 닫히고 텍스트만 열린다.
- 표시 토글 클릭 시 편집기 열림 상태가 바뀌지 않는다.
- 위/아래 이동 후 번호와 실제 배열 순서가 일치한다.
- 복제 후 복제 블록이 원본 바로 다음 위치에 생긴다.
- 삭제 후 선택 상태가 남지 않는다.
- 드래그 순서 변경이 계속 동작한다.

### 11.2 편집기

- `히어로 편집` 중복 제목이 보이지 않는다.
- 탭이 블록 옵션에 맞게 표시된다.
- 탭 전환 시 입력값이 사라지지 않는다.
- 내용 섹션이 기본으로 열려 있다.
- 고급 섹션은 기본으로 닫혀 있다.
- 제목과 설명이 별도 카드가 아니라 동일한 폼 흐름으로 보인다.
- 필드, 그룹, 탭의 깊이가 시각적으로 구분된다.
- 저장과 미리보기 연결이 유지된다.

### 11.3 뷰포트

데스크톱 편집 영역 폭을 최소 두 가지로 확인한다.

- 왼쪽 작업 영역 약 `640px`
- 왼쪽 작업 영역 약 `720px`

확인 항목:

- 아이콘 버튼 겹침 없음
- 긴 블록명 말줄임 정상
- 메뉴나 tooltip이 잘리지 않음
- 하단 추가 dock과 편집기가 겹치지 않음

## 13. 완료 기준

아래 조건을 모두 만족해야 완료로 처리한다.

- 화면 순서 행을 다시 누르면 닫힌다.
- 위/아래/복제/삭제가 행에서 직접 보인다.
- `...` 메뉴가 주요 기능의 유일한 접근점이 아니다.
- 블록 이름과 `OO 편집`이 중복되지 않는다.
- 편집기 상단에 블록별 탭이 있다.
- 탭 내부 섹션은 카드가 아니라 구분선으로 나뉜다.
- 입력 필드는 중첩 카드로 보이지 않는다.
- Hero, Text, Image, Links, Form에서 같은 조작 문법을 사용한다.
- 드래그, 표시, 이동, 복제, 삭제가 모두 동작한다.
- 저장과 미리보기 연결이 유지된다.
- 모바일 편집 기능을 추가하지 않는다.
- 공개 메인 보호 파일 diff가 없다.
- `npm run mojibake:qa`와 `npm run build`가 통과한다.

## 14. 작업자 금지사항

- 기능을 디자인 단순화를 이유로 제거하지 않는다.
- 직접 노출하기로 한 기능을 `...` 메뉴에 다시 숨기지 않는다.
- 모든 요소에 굵은 외곽선과 그림자를 추가하지 않는다.
- 기존 CSS 위에 더 강한 `!important` 묶음만 계속 추가하지 않는다.
- 블록 데이터 스키마를 UI 편의를 위해 변경하지 않는다.
- 공개 메인, 라우팅, 서버, Functions를 자동 수정하지 않는다.
- 한 번에 모든 블록을 수정하고 마지막에만 검증하지 않는다.
- 모바일 편집 화면을 새로 만들지 않는다.
